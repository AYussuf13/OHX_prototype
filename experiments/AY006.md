# OHX Experiment AY006 — Software Meets Hardware

**Date:** 10 August 2026  
**Status:** Successful prototype integration

## Objective

Connect the physical OHX prototype to the web dashboard and establish real-time communication between the ESP32/BME688 sensor system and the browser.

## What was built

AY006 moves OHX from separate hardware and software prototypes to an integrated device-dashboard system.

The ESP32 now streams live sensor data directly to the OHX web dashboard using Web Serial.

The firmware remains the source of truth for the measurement workflow:

PREPARE → CALIBRATE → READY → BREATHE → ANALYSING → RECOVER → CALIBRATE → READY

The dashboard mirrors these states in real time and displays:

- Gas resistance
- Humidity
- Temperature
- Device baseline
- Warm-up and calibration countdowns
- Live sensor response
- Breath events
- Breath and recovery curves

## Breath Results

Completed breath measurements are now stored within the active session.

For each breath, the dashboard can display:

- Device breath ID
- Baseline gas resistance
- Minimum gas resistance
- Maximum response (%)
- Gas resistance at breath detection
- Gas resistance at recovery
- Captured breath curve
- Recovery curve
- Session metadata

The breath response displayed by the dashboard is taken directly from the firmware `BREATH_COMPLETE` event rather than independently re-detected by the frontend.

## Bidirectional Communication

AY006 also introduced dashboard → device communication.

The ESP32 firmware now accepts:

`END_SESSION`

When received, the firmware enters:

`SESSION_COMPLETE`

New breath tests are disabled while sensor communication remains active.

This was validated through the web dashboard:

Dashboard → Web Serial → ESP32 → SESSION_COMPLETE → TFT displays COMPLETE

## Current Architecture

Breath
↓
BME688
↓
ESP32
↓
OHX firmware

Commands can also travel in the opposite direction:

OHX dashboard → Web Serial → ESP32

## Outcome

AY006 successfully demonstrated end-to-end integration between the OHX physical prototype and web application.

The prototype can now acquire a physical breath response, process the measurement through the ESP32 state machine, stream the data to the browser, visualise the response and recovery, store the completed breath result, and receive device-control commands from the dashboard.
