# OHX Experiment AY005 — Breath Collection Dataset

**Date:** 10 August 2026  
**Status:** Completed — larger-scale data collection paused pending sampling-system redesign

## Objective

Validate the updated OHX breath-measurement workflow and determine whether the system is ready for larger-scale data collection and machine-learning development.

## What I developed

The ESP32 firmware and Python logging system were tested together using the updated measurement workflow:

**Warm-up → Calibration → Ready → Breath detection → Analysis → Recovery → Recalibration → Ready**

The firmware establishes a baseline, detects a breath when gas resistance falls ≥30% relative to the frozen baseline, records the minimum gas resistance, and calculates the percentage response.

New measurements are prevented while the sensor is recovering.

A 60-second baseline drift window was also implemented. If the window mean remains within 5% of the existing baseline, the baseline can be refreshed. If the difference exceeds 5%, the existing baseline remains frozen.

The Python acquisition and analysis pipeline records:

- Raw BME688 measurements
- Device states
- Breath IDs
- Baseline values
- Breath events
- Breath response
- Session metadata

The analysis pipeline was also extended to extract:

- Maximum response (%)
- Response AUC (%·s)
- Recovery time
- Peak humidity
- Humidity increase

---

## Initial Validation — S002

Three standardised breath measurements were collected.

| Breath | Baseline (kΩ) | Minimum (kΩ) | Response |
| ------ | ------------- | ------------ | -------- |
| 1 | 179.745 | 103.101 | **42.640%** |
| 2 | 176.230 | 101.931 | **42.160%** |
| 3 | 178.864 | 102.543 | **42.670%** |

**Mean response:** 42.49%  
**SD:** 0.286 percentage points  
**CV:** 0.67%

The three measurements were closely clustered, suggesting that the updated measurement workflow can produce repeatable sensor responses under these conditions.

However, this result alone does not establish repeatability of the overall sampling system.

---

## S003 — Important Observation

A second session produced greater response variation:

| Breath | Response |
| ------ | -------- |
| 1 | **44.939%** |
| 2 | **35.188%** |
| 3 | **38.073%** |
| 4 | **34.774%** |

**Mean response:** 38.244%  
**SD:** 4.699 percentage points  
**CV:** 12.29%

This prompted reconsideration of the physical breath-sampling setup.

The current prototype consists of a mouthpiece and small syringe chamber followed by an approximately **3 cm open-air gap** before the BME688.

As a result, exhaled breath can mix with ambient air before reaching the sensor. Sensor angle, airflow, exhalation technique and room-air movement may therefore influence the concentration and flow of breath reaching the BME688.

The variation observed in S003 cannot currently be attributed confidently to breath composition, breathing technique or sampling geometry.

---

## Key Learning

**The physical enclosure is part of the measurement system, not simply the product casing.**

Before collecting the primary dataset for machine-learning development, OHX requires a more controlled and reproducible sampling geometry.

The next physical prototype should preserve the useful characteristics of the current setup while introducing a defined flow path:

**Removable mouthpiece → small primary chamber → controlled sensing region → fixed BME688 position → defined exhaust**

The aim is to reduce uncontrolled ambient-air mixing and improve consistency in how exhaled breath reaches the sensor.

AY005 also identified the need for **sample-quality control**.

A future OHX system should be capable of determining whether a breath manoeuvre is sufficiently consistent before accepting the measurement. Potential indicators include:

- Humidity change
- Breath-response shape
- Breath duration
- Potential future flow or pressure measurement

These require further investigation before being used as acceptance criteria.

---

## Decision

Large-scale machine-learning data collection is **paused until the physical sampling geometry is better controlled**.

The current dataset remains useful for engineering development, pipeline validation and comparison with future enclosure designs, but it should not be treated as the primary ML training dataset.

The existing firmware and acquisition pipeline will remain relatively stable while the physical sampling system is redesigned.

---

## Next Steps

1. Develop and 3D-print the first controlled breath-sampling enclosure.
2. Repeat the S002/S003 repeatability experiment using the enclosed system.
3. Compare measurement variability before and after enclosure development.
4. Investigate objective breath sample-quality indicators.
5. Once sampling geometry is sufficiently reproducible, begin structured dataset collection for ML.
6. In parallel, integrate the OHX dashboard with live device data.

---

## Outcome

AY005 demonstrated that the updated OHX firmware and data pipeline can capture structured, repeatable breath-response measurements.

More importantly, the experiment identified **sampling geometry as a major uncontrolled variable** and changed the immediate development priority from increasing dataset size to improving measurement control.

This finding directly informed the next stage of OHX hardware development.
